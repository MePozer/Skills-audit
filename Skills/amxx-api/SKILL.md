# Поверхность API AMX Mod X

Стек: HLDS 8684, ReHLDS 3.15.0.896, ReGameDLL 5.30.0.814, Metamod-R 1.3.0.149, AMX Mod X 1.10.0.5484, ReAPI 5.29.0.358. Правила проверены на этих версиях. Если в папке сервера версии другие — сверяйся с её файлами, а не с этим текстом. Пометка в скобках у правила говорит, чем оно подтверждено; искать по ней ничего не нужно. Полная таблица проверок — в `references/evidence.md`.

## Когда применять

- выбор функции AMXX для задачи
- перенос кода из SA-MP или open.mp
- ошибка компилятора про неизвестную или неверную функцию
- вопрос «есть ли в AMXX такая функция»

## Когда не применять

- флаги и вывод компилятора
- прекэш и бюджет ресурсов
- состояние игрока, сущности, меню
- права и клиентский ввод
- хранение данных

## Жёсткие запреты

1. **Не использовать 13 объявлений с `#pragma deprecated` в заголовках AMXX 1.10.0.5484** — Компилятор помечает их предупреждением, но не ошибкой, поэтому они тихо живут в коде. Список прочитан прямо в дереве заголовков на пине, шесть файлов. *(доказательство: чтение исходников на пине)*

| Устаревшее | Где | Чем заменяется |
| --- | --- | --- |
| `socket_change` | `sockets.inc` | `socket_is_readable()` |
| `client_disconnect` | `amxmodx.inc` | `client_disconnected()` |
| `md5` | `amxmodx.inc` | `hash_string()` |
| `md5_file` | `amxmodx.inc` | `hash_file()` |
| `plugin_modules` | `amxmodx.inc` | не нужен: модули подключает компилятор |
| `require_module` | `amxmodx.inc` | не нужен: ничего не делает |
| `is_amd64_server` | `amxmodx.inc` | не нужен: всегда 0 |
| `geoip_code2` | `geoip.inc` | `geoip_code2_ex()` |
| `geoip_code3` | `geoip.inc` | `geoip_code3_ex()` |
| `geoip_country` | `geoip.inc` | `geoip_country_ex()` |
| `ns_takedamage` | `ns.inc` | HamSandwich |
| `get_customdir` | `amxmisc.inc` | `get_configsdir()` |
| `strbreak` | `string_stocks.inc` | `argbreak()` |

Пометки `@deprecated` в комментарии без `#pragma` в этот счёт не входят: пять констант меню в `newmenus.inc:90-97` (`MEXIT_NORMAL`, `MENUPAD_NONE`, `MENUPAD_PAGE`, `MPROP_ORDER`, `MPROP_PADMENU`) и natives стиля 1 (`amxmodx.inc:2696`, `:2747`). Они тоже не используются, но компилятор о них молчит. *(доказательство: чтение исходников на пине)*

2. **Не переносить приёмы из SA-MP и open.mp в код AMXX** — Это другая платформа и другой набор функций. В AMXX 1.10 нет `foreach`, нет `mysql_format`, нет `y_hooks`, нет `SendClientMessage`, нет `GetPlayerPoolSize`, нет `OnPlayerUpdate`. Проверено по дереву заголовков: файла `foreach.inc` в поставке нет вообще, а для базы данных есть только `sqlx.inc`. Код, написанный по гайдам SA-MP, в AMXX не соберётся. *(доказательство: чтение исходников на пине)*

## Как делать правильно

1. **Перед использованием незнакомой функции искать её в дереве заголовков на пине** — 66 файлов `.inc` в `addons/amxmodx/scripting/include` — это точная поверхность API закреплённой сборки. Поиск по имени даёт ответ быстрее и надёжнее, чем память или форум. *(доказательство: чтение исходников на пине)*
2. **Проверять сигнатуру и возвращаемое значение по заголовку, а не по примеру из интернета** — Пример мог быть написан для другой сборки. *(доказательство: чтение исходников на пине)*
3. **`create_cvar` предпочитать, когда нужны описание и границы значения** — Он даёт то же самое плюс описание, минимум и максимум, и эти сведения попадают в конфиг AMXX. *(доказательство: чтение исходников на пине)*
4. **Помнить, что `register_cvar` помечен устаревшим в комментарии, а не компилятором** — В `cvars.inc:72` у него стоит `@note Deprecated. Consider to use create_cvar for more options.`, но `#pragma deprecated` у него нет: предупреждения компилятор не даёт, и сам AMXX использует его в `amxmisc.inc`. Новый код писать на `create_cvar`, уже написанный вызов `register_cvar` ошибкой не является. *(доказательство: чтение исходников на пине)*
5. **Для базы данных использовать только `sqlx`** — В закреплённой сборке есть `sqlx.inc` и нет никакого `mysql_*`. Асинхронный запрос — `SQL_ThreadQuery`, обработчик выполняется на главном потоке. *(доказательство: чтение исходников на пине)*
6. **Перед `ArrayGetCell`, `ArrayGetString` и записью по индексу проверять `ArraySize` и границы** — Пустой массив или индекс вне диапазона даёт runtime error 10. На рабочей ZP-сборке это уже произошло с ambience при пустом списке режимов. *(доказательство: чтение исходников на пине; лог живого сервера)*
7. **Перед ручным парсером проверить штатные `textparse_ini.inc`, `textparse_smc.inc` и `json.inc`** — На пине есть 7 INI-, 8 SMC- и 58 JSON-нативов. Для нового плагина использовать штатный парсер, если формат ему соответствует; исходный парсер ZP 5.0.8a не переписывать ради «модернизации». *(доказательство: чтение исходников на пине; решение проекта не менять оригинал ZP)*
8. **Для новых плагинов сначала проверять специализированные заголовки** — `gameconfig.inc` даёт 6 нативов для offsets/keys/addresses вместо сырых чисел, `datapack.inc` — 12 нативов для передачи данных через задачи и форварды, `xs.inc` — 95 готовых стоков строк и массивов. Не писать дублирующий код, пока нужная операция уже есть на пине. *(доказательство: чтение исходников на пине)*
9. **Не определять `MEMBER_UNSAFE` перед `#include <reapi>`** — Без него `get_member` и `set_member` разворачиваются в безопасные `_s`-версии; макрос явно отключает эти проверки. *(доказательство: чтение исходников ReAPI 5.29.0.358)*
10. **Не превращать выбор API в слепую лестницу `register_event → Ham → ReAPI`** — Сначала использовать публичный native/forward самого мода; для наблюдения за сетевым событием подходит `register_event`; для функции GameDLL/engine с прямой цепочкой — ReAPI; Ham нужен там, где прямой цепочки нет. У ZP прямой эквивалент ReAPI есть у 87 из 102 Ham-регистраций, но `Ham_Touch`, `Ham_Use` и `Ham_Think` (15 регистраций) полного эквивалента не имеют. *(доказательство: чтение исходников ZP 5.0.8a и ReAPI 5.29.0.358)*
11. **До кода с ReAPI подтверждать модуль командой `amxx modules`** — Наличие `reapi_amxx.dll` и строки в `modules.ini` не доказывает загрузку. **Подтверждено живым сервером 20.09.2026:** `12 modules, 12 correct`, `ReAPI 5.29.0.359 Asmodai & s1lent running`, источник `pl1` — модуль поднялся автоматически, потому что его требует плагин. Строка версии — `v5.29.0.359-dev`, хотя релиз помечен `5.29.0.358`: номер берётся сборкой из счётчика коммитов, поэтому версию подтверждать выводом модуля, а не именем архива. *(доказательство: замер на живом сервере)*
12. **Из ReZombie брать только архитектурные идеи, не код** — Полезны три слоя (API → общее ядро → контент), объекты на хендлах, свойства через enum и пары `_pre`/`_post`. Различать источники: архитектурные идеи — `fl0werD/rezombie` и `fl0werD/rezombieplague`; у `fl0werD/rezombieplague` лицензии нет, поэтому его код брать нельзя. API ReZombiePlague не объявляет `register_library`, `LibraryExists` и `#pragma reqlib`; в новом ядре этот контракт зависимости надо добавить, а не копировать отсутствие проверки. *(доказательство: чтение исходников ReZombiePlague; лицензия не найдена)*

## Проверка перед выдачей кода

1. Сборка: `0 errors, 0 warnings`, `debug >= 1` (без `-d0`).
2. Ни одно объявление из таблицы выше в коде не используется.
3. Ни одна функция из списка «чего нет в AMXX» в коде не используется.
4. Каждый вызов незнакомой функции сверен с заголовком на пине.
