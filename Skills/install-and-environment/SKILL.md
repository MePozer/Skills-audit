# Установка и окружение сервера

Стек: HLDS 8684, ReHLDS 3.15.0.896, ReGameDLL 5.30.0.814, Metamod-R 1.3.0.149, AMX Mod X 1.10.0.5484, ReAPI 5.29.0.358. Правила проверены на этих версиях. Если в папке сервера версии другие — сверяйся с её файлами, а не с этим текстом. Пометка в скобках у правила говорит, чем оно подтверждено; искать по ней ничего не нужно. Полная таблица проверок — в `references/evidence.md`.

## Когда применять

- развёртывание и переустановка сервера
- ошибки запуска и установки
- конфиги, каталоги, порты, FastDL
- профили ботов и .nav

## Когда не применять

- выбор версии компонента
- лицензии сторонних проектов
- код плагина

## Жёсткие запреты

Нарушение любого пункта либо убивает сервер, либо тихо портит данные.

1. **Не держать посторонних plugins-*.ini в каталоге configs** — AMXX сам загружает любой configs/plugins-*.ini: изоляция прогонов ломается молча, и вывод о причине получается неверным. *(доказательство: замер на живом сервере)*
2. **Релизный game_init.cfg не заменять целиком, править одно значение** — Более ранние версии установщика молча выбрасывали две настройки релиза (hostage_ai_enable, mp_hullbounds_sets). В текущей сборке файл берётся как есть, и в отчёте печатаются его размер и sha256 до и после правки. *(доказательство: замер на живом сервере)*

## Как делать правильно

1. **Дать движку свой Steam-комплект рядом с сервером и подменить значение реестра на время прогона** — Движок спрашивает у Windows, какой steamclient.dll брать, через HKCU\Software\Valve\Steam\ActiveProcess\SteamClientDll. На машине с клиентом Steam там прописан клиентский файл, и сервер падает с Unable to initialize Steam. Значение возвращать в finally. *(rehlds/ReHLDS#627, ValveSoftware/halflife#2667; доказательство: официальный источник)*
2. **Ставить 8684 из официального архива с проверкой sha256, SteamCMD эталоном не считать** — SteamCMD даёт смешанную установку: докачивает свежие клиентские файлы поверх легаси-архива (steam_api.dll 2012 рядом с steamclient.dll 2026). *(доказательство: замер на живом сервере)*
3. **Полноту установки проверять по отпечаткам файлов, а не по коду возврата** — App 90 не сходится при validate: «Success! App '90' fully installed» четыре раза подряд, каждый проход заново качает те же примерно 2,1 МБ. *(доказательство: замер на живом сервере)*
4. **Профили ботов ставить отдельным архивом regamedll/extra/zBot/bot_profiles.zip в корень сервера** — Без BotProfile.db GetRandomProfile() возвращает null (cs_bot_manager.cpp:818-821), и боты не входят: «All bot profiles at this difficulty level are in use». *(доказательство: чтение исходников на пине)*
5. **Отсутствие файлов .nav считать нефатальным, ходячие боты — отдельная задача** — В официальном архиве 8684 ноль файлов .nav, Valve их не поставляет. Боты заходят и стоят: ошибка нефатальна. *(доказательство: замер на живом сервере)*
6. **Перед прогоном снимать зависшие hlds.exe и проверять порт реальной привязкой UDP** — Фатальная ошибка движка показывает модальное окно: процесс жив и держит сокет, следующий прогон падает через 7 секунд с NET_OpenIP и map «(null)». *(доказательство: замер на живом сервере)*
7. **Ставить фреймворк вместе с его конфигами и переводами** — ZP 5.0.8a поставляет только код: без configs/ и data/lang/ сообщения выходят сырыми ключами, а плагин не находит словарь. *(доказательство: замер на живом сервере)*
8. **В отправляемом пакете держать пару исходник плюс бинарник с совпадающими хешами** — Перекомпилированный .amxx без рядом лежащего .sma делает доказательство непроверяемым. Сверять sha256 обоих и указывать в README. *(доказательство: замер на живом сервере)*
9. **Прогоны разводить по портам** — Каждый прогон занимает свой порт; иначе второй падает на привязке, и это выглядит как отказ движка. *(доказательство: замер на живом сервере)*
10. **Ни один слой не проверять «по наличию файла»** — Проверка идёт по meta list, списку загруженных модулей и версии AMXX, снятым на работающем сервере. *(доказательство: замер на живом сервере)*
11. **Скачивать только со страницы релиза upstream-проекта** — Никогда — с сайтов готовых сборок, файлопомоек, описаний под видео и «зеркал». *(доказательство: официальный источник)*
12. **AMXX base и CS addon держать одной и той же сборки** — Смешивание разных build numbers недопустимо. *(доказательство: официальный источник)*
13. **Держать delta.lst в соответствии с релизом** — Официальная таблица называет файл обязательным: Network delta definitions shipped with the current build. Наш установщик его копирует. *(доказательство: документация upstream)*

14. **`game.cfg` считать необязательным: ReGameDLL читает его, только если файл есть** — В нашей сборке файла нет, есть только `game_init.cfg` (89 байт, CRLF, `bot_enable 1`), и сервер работает на дефолтах ReGameDLL. Отсутствие `game.cfg` — не дефект установки. *(доказательство: замер на живом сервере)*
15. **Анти-флуд и анти-спидхак cvars прописывать в `server.cfg` явно** — Для ReHLDS 3.15.0.896 зафиксировать `sv_rehlds_movecmdtime_max_warnings -1`, чтобы не включать путь краша #1198, и оставить независимые лимиты команд на точных дефолтах пина: `max_avg 1800`, `max_burst 5500`, оба `*_punish 5` (см. `security`). *(доказательство: чтение официального исходника на пине)*
16. **Один плагин отключать словом `disabled` после имени в `plugins.ini`, а отладку включать словом `debug`** — Это второй токен строки, не отдельная директива. `disabled` полностью пропускает загрузку; `debug` требует, чтобы `.amxx` уже содержал debug-информацию. Символ `;` обрывает остаток строки. *(доказательство: чтение исходников на пине)*
17. **Для FastDL не выкладывать рядом `*.bz2` и не считать доставку заменой прекэша** — GoldSrc не запрашивает имя с двойным расширением через этот путь. Сервер всё равно обязан прекэшить каждый ресурс на карте, а доставку проверяют отдельно на чистом клиенте. Живой тест FastDL нашей сборки ещё открыт. *(доказательство: официальная документация upstream; статус живого теста — открыто)*

## Проверка перед выдачей кода

1. Сборка: `0 errors, 0 warnings`, `debug >= 1` (без `-d0`).
2. Ни одно правило из раздела «Жёсткие запреты» не нарушено.
3. У каждого правила, попавшего в код, есть источник в этом файле.
