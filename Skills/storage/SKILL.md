# Хранение данных

Стек: HLDS 8684, ReHLDS 3.15.0.896, ReGameDLL 5.30.0.814, Metamod-R 1.3.0.149, AMX Mod X 1.10.0.5484, ReAPI 5.29.0.358. Правила проверены на этих версиях. Если в папке сервера версии другие — сверяйся с её файлами, а не с этим текстом. Пометка в скобках у правила говорит, чем оно подтверждено; искать по ней ничего не нужно. Полная таблица проверок — в `references/evidence.md`.

## Когда применять

- сохранение статистики, настроек, прогресса
- nvault или база данных
- асинхронные запросы и передача данных в ответ

## Когда не применять

- прекэш
- сущности и меню
- безопасность команд
- стоимость форвардов
- сборка

## Жёсткие запреты

Нарушение любого пункта либо убивает сервер, либо тихо портит данные.

1. **Не полагаться на номер игрока между отправкой запроса и ответом** *(доказательство: чтение исходников на пине)*
2. **Синхронный SQL использовать только для мелких операций при старте** — Он блокирует сервер. *(доказательство: чтение исходников на пине)*
3. **Имя vault — короткий литерал: никогда не из конфига, не из переменной, не от игрока** — Имя попадает в sprintf в буфер 255 байт. *(доказательство: чтение исходников на пине)*

## Как делать правильно

1. **Длину ключа и значения nvault проверять самому** — Ключ не длиннее 255 байт, значение не длиннее 65 535. Модуль не проверяет, а длина ключа молча приводится к одному байту. *(доказательство: чтение исходников на пине)*
2. **Имя vault держать коротким литералом в коде** — Оно попадает в sprintf в буфер 255 байт. *(доказательство: чтение исходников на пине)*
3. **В SQL_ThreadQuery проверять всё, что пришло снаружи** — Игрок мог выйти, карта смениться; нужное передавать через data[]. *(доказательство: чтение исходников на пине)*
4. **Выбор SQL-сервера определять по версии клиентской библиотеки внутри mysqlx** — Не по тому, что «сейчас принято ставить». *(доказательство: чтение исходников на пине)*
5. **Для новых плагинов предпочитать штатный `json.inc` вместо ручной сборки строк** — В AMXX 1.10 это 58 нативов: `json_parse` (строка или файл), `json_validate` против схемы, `json_serial_to_file`, доступ по точкам, `json_deep_copy`. Оригинальный ZP 5.0.8a так не делает — это путь для нового кода, а не повод переписывать baseline. *(доказательство: чтение заголовков на пине)*

## Что проверять и помнить

1. **nvault закрывать явно только если файл нужен сразу** — Модуль сохраняется при выгрузке плагинов, то есть при смене карты. *(доказательство: чтение исходников на пине)*

## Проверка перед выдачей кода

1. Сборка: `0 errors, 0 warnings`, `debug >= 1` (без `-d0`).
2. Ни одно правило из раздела «Жёсткие запреты» не нарушено.
3. У каждого правила, попавшего в код, есть источник в этом файле.
