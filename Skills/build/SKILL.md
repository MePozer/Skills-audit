# Сборка плагина

Стек: HLDS 8684, ReHLDS 3.15.0.896, ReGameDLL 5.30.0.814, Metamod-R 1.3.0.149, AMX Mod X 1.10.0.5484, ReAPI 5.29.0.358. Правила проверены на этих версиях. Если в папке сервера версии другие — сверяйся с её файлами, а не с этим текстом. Пометка в скобках у правила говорит, чем оно подтверждено; искать по ней ничего не нужно. Полная таблица проверок — в `references/evidence.md`.

## Когда применять

- сборка плагина и чтение вывода компилятора
- флаги сборки и уровень debug
- проверки на этапе компиляции
- контроль размера плагина

## Когда не применять

- диагностика сбоев сервера
- прекэш
- сущности и меню
- хранение данных
- безопасность
- производительность

## Жёсткие запреты

Нарушение любого пункта либо убивает сервер, либо тихо портит данные.

1. **Не использовать #pragma amxlimit и ключ -X** — Срабатывание предела валит компилятор без сообщения. *(доказательство: запуск в песочнице)*
2. **Не навязывать `#pragma semicolon 1` как правило безопасности или качества** — Это только синтаксический режим. Из 26 `.sma` самой AMXX его не использует ни один, а ReZombiePlague использует во всех 69 файлах; ни один замер не показал вреда или пользы для runtime. В существующем коде сохранять выбранный стиль, в новом — выбрать один стиль на весь проект и не смешивать. *(доказательство: чтение исходников AMXX и ReZombiePlague; решение проекта)*

## Как делать правильно

1. **Утверждение о компиляторе проверять запуском компилятора, а не чтением его исходников** *(доказательство: запуск в песочнице)*
2. **Успех сборки подтверждать кодом возврата: 0 — успех, 139 — падение компилятора** — Падение компилятора не является ошибкой в коде плагина. *(доказательство: запуск в песочнице)*
3. **Плагин считать собранным только при «0 errors, 0 warnings»** — Формулировка «должно собраться» не принимается. *(доказательство: запуск в песочнице)*
4. **Для проверки значений на этапе компиляции использовать #if с #error, а не #assert** — При debug 0 #assert пропускается молча и ничего не проверяет. *(доказательство: запуск в песочнице)*
5. **Указывать в отчёте отпечаток компилятора: версия и sha256 обоих файлов** *(доказательство: запуск в песочнице)*
6. **Собирать релизные плагины с debug не меньше 1** — При -d0 выход за границу массива перестаёт быть ошибкой и становится порчей памяти. Эталон — собственная сборка AMXX, plugins/compile.sh. *(доказательство: чтение исходников на пине)*

7. **Помнить, что `plugins.ini` понимает два слова после имени плагина: `debug` и `disabled`** — `debug` включает runtime-отладчик без повторной сборки, но только если `.amxx` уже собран с debug-информацией (`-d1` и выше); бинарник после `-d0` не загрузится с ошибкой `Plugin not compiled with debug option`. `disabled` пропускает плагин целиком, не удаляя строку. Разбор строки — `sscanf(line, "%s %s", pluginName, debug)` в `CPlugin.cpp:107`, символ `;` обрывает строку в любом месте. *(доказательство: чтение исходников на пине)*
8. **Новый код писать на `create_cvar`, существующий `register_cvar` ошибкой не считать** — У `register_cvar` только пометка `@note Deprecated` в комментарии, `#pragma deprecated` у него нет: компилятор предупреждения не даёт, и сам AMXX использует его внутри. `create_cvar` предпочитать в новом коде ради описания и границ значения. Число 13 — это всего устаревших объявлений в 6 заголовках, а не вызовов `register_cvar`. *(доказательство: чтение заголовков на пине; владелец нюанса — `amxx-api`, правило 4)*

## Проверка перед выдачей кода

1. Сборка: `0 errors, 0 warnings`, `debug >= 1` (без `-d0`).
2. Ни одно правило из раздела «Жёсткие запреты» не нарушено.
3. У каждого правила, попавшего в код, есть источник в этом файле.
